# Rule: Always Ask When Intent Is Unclear

If the user's request is ambiguous, underspecified, or unclear in any way:
- STOP immediately
- DO NOT assume or guess at intent
- ASK the user a direct clarifying question before taking any action

This applies to all tasks — code changes, feature requests, architecture decisions, and deployments.

Examples of when to ask:
- The user says "fix this" without specifying what is broken
- The user says "make it better" without defining what "better" means
- The user describes a desired outcome that could be achieved multiple different ways

Never build the wrong thing. One good clarifying question saves hours of rework.
